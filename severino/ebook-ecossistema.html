Parte 1

A Visão: o que é um Ecossistema de Vendas IA

É uma máquina de vendas autônoma: um conjunto de programas (agentes) que trabalham em equipe dentro de um servidor, sem humanos no meio, transformando atenção em dinheiro.

Cada agente tem um papel claro e conversa com os outros através de um barramento de eventos — como numa esteira de fábrica. O orquestrador lê cada evento e roteia para o agente certo.

redes / site / bot │ ▼ CAPTADOR (atrai) ─► lead.novo │ ▼ QUALIFICADOR (pontua) ─► lead.qualificado │ ▼ NUTRIDOR (educa) ─► lead.quente │ ▼ CONVERSOR (vende) ─► venda.proposta │ ▼ ONBOARDER (entrega) ─► trial.ativado │ ▼ RETENTOR + COBRADOR (pós-venda) │ ▼ ANALISTA → ESTRATEGISTA (fecha o ciclo)
⚙️ Regra de ouro: os agentes não se chamam diretamente — postam eventos no barramento e o orquestrador roteia. Isso garante rastreabilidade, resiliência e testes.

Servidores Node.js + ffmpeg + Postiz rodam bem em 4 GB. A VPS é onde tudo mora: sites, bot, agentes, conteúdo e dados (JSON em arquivos — sem banco SQL).

2.2 Software base no servidor

  • Node.js ≥ 18 — runtime de tudo
  • PM2 — mantém serviços online, reinicia sozinho
  • Nginx — servidor web / proxy reverso + SSL
  • Certbot / Let's Encrypt — HTTPS grátis
  • ffmpeg 6.x — geração e animação de vídeos/cards
  • git — versionamento + backups

3.2 O ciclo de um lead (exemplo real)

Postiz (redes) ─► Captador: lead.novo └► Qualificador: lead.qualificado (quente) └► Nutridor: 2-3 conteúdos educativos └► Conversor: 1:1; aceita trial → venda.proposta └► Onboarder: POST /api/trial → onboarding.ok └► Retentor: upsell → venda.confirmada └► Cobrador → Analista → Estrategista ajusta

3.3 Configuração por produto (desacoplamento)

O núcleo é independente dos produtos. O plug-in é produtos.json:

{ "id": "btcweather", "nome": "BTC Weather Panel", "plano": "R$ 47/mês", "checkout": "https://pay.kiwify.com.br/...", "ativacao": { "tipo": "trial", "endpoint": "/api/trial" } }

Lançar produto novo = só criar uma entrada. Zero mudança no núcleo.

Parte 4

O Passo a Passo por Fases

Princípio de escalagem: cada fase termina com uma meta alcançada → review (o que converteu, CPL, tempo de ciclo) → escalar só o canal que provou.

Fase 0 — Fundação (1–2 dias)

  1. VPS + Node + PM2 + Nginx + SSL configurados
  2. produtos.json com o primeiro produto
  3. ia.js: wrapper LLM (retry, timeout, contador de tokens)
  4. Barramento: queue/events.jsonl + pendentes.json + postar()/ler()
  5. Orquestrador PM2 (loop 1s, max_hops=5, heartbeat)
  6. Guardião mínimo (ética + custo)
  7. Rotas /api/ecosystem/* protegidas

Entregável: orquestrador no ar, publicando/consumindo eventos. ✅

Fase 1 — Núcleo de Vendas (3–5 dias)

  1. Agentes LLM: Estrategista, Captador, Qualificador, Nutridor, Conversor
  2. canais.js + guardiao.js (filtro ético em toda saída)
  3. Estado por lead: data/funil.json
  4. Onboarder ativando trial real (POST /api/trial)
  5. Retentor básico (follow-up pós-trial)
  6. Dupla captura no site (e-mail → Telegram via ?start=CODIGO)

Entregável: lead entra no funil e sai com trial ativado, rastreado. ✅

Fase 2 — Divulgação 24/7 (2–3 dias)

  1. Postiz self-hosted + publicação automática (X + Instagram)
  2. Gerador de card diário (clima_card.json → PNG + overlay)
  3. Animador de vídeo (MP4 de loop perfeito com céu do clima, ffmpeg)
  4. Cron diário: postar → gerar → animar → publicar
  5. Sequências de e-mail/WhatsApp com anti-spam

Entregável: conteúdo automático diário em X e Instagram. ✅

Fase 3 — Vendas & Cobrança (2–3 dias)

  1. Webhook Kiwify → venda.confirmada no barramento
  2. Conversor integra checkout e pós-venda
  3. Cobrador: garantia/reembolso automático + avisos de vencimento
  4. E-mail obrigatório no trial (alimenta o funil)

Entregável: venda paga → entrega + cobrança + garantia sem humano. ✅

Fase 4 — Multi-Produto (2–3 dias)

  1. Qualificador decide o produto certo por lead
  2. Conversor/Onboarder paramétricos via produtos.json
  3. Vitrine consumindo produtos.json
  4. Um bot atende todos os produtos (onboarding unificado)

Entregável: funil multicase rodando. ✅

Fase 5 — Lançamento de Novos Micro-SaaS

Regra: só lançar novo produto se o case anterior provou trial→pago ≥ 5%. Novo produto recicla captura, bot, funil, checkout e e-mail.

  • Auto-bio / legendas com IA
  • Relatório diário de mercado (outras criptos)
  • Bot de vendas como serviço

Fase 6 — Escala Pós-100 Pagantes

  • Escalar só o canal campeão (melhor CPL)
  • Tráfego pago com pixel de conversão instalado
  • Programa de indicação (referral)
  • Jornada pós-venda: onboarder → retentor → cross-sell

Parte 6

Custos e Economia

ItemCusto mensal
VPS (2 vCPU / 4 GB)R$ 40–70
Domínio (amortizado)R$ 3–8
LLM (modelo barato, orçado)R$ 10–40
TotalR$ 60–120/mês

Alavancas de economia

  • Modelo barato por padrão, forte só quando necessário
  • Orçamento de tokens/dia — Guardião bloqueia excesso
  • Rate limiting por IP/endpoint
  • Prospeção orgânica (X, IG, Reddit) sem tráfego pago no começo
  • Cards/vídeos gerados no próprio servidor com ffmpeg
💡 Regra do fundador: provar no pequeno → medir → escalar só o que converteu. Custo fica baixo até existir prova de CPL.

Conclusão

Você Pode Construir Isso

O Severino não é mágica: é uma VPS barata + uma fila de eventos + agentes de IA com papéis claros + conteúdo automático + um funil rastreado de ponta a ponta.

Você monta em fases, prova no pequeno e escala só o que converteu. O ecossistema trabalha 24/7: prospecta, educa, vende, entrega, cobra e relata — enquanto você dorme.

A IA não veio substituir o empreendedor. Ela veio garantir que nenhum lead seja desperdiçado.
